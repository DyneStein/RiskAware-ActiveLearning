# OOD Evaluation (Out-of-Distribution)

This directory contains the pipeline to evaluate trained models against an external test set, testing their generalisation and safety when deployed on out-of-distribution (OOD) clinical data.

## Setup Instructions

If you wish to re-run the OOD evaluation, you must provide the data and trained model checkpoints:

1. **Dataset**: Place the test images directly inside `Data/` alongside your ground truth CSV.
   - Images go in: `Data/*.jpg`
   - CSV goes in: `Data/ground_truth.csv` (or any other `.csv` name)
   
   > [!TIP]
   > **How to Reproduce with Your Own Images**
   > To evaluate your own custom images, drop the images into the `Data/` folder. Next, open `ground_truth.csv` and add a new row for each image. 
   > Put the name of the image (without the `.jpg` extension) in the first column, and place a `1.0` under the column that represents its true skin lesion diagnosis (and `0.0` for all other columns).
   > For your convenience, we have already included 3 template images (`temp1.jpg`, `temp2.jpg`, `temp3.jpg`) and pre-filled their rows in the CSV so you can see exactly how it should be formatted!

2. **Models**: Place the `.pt` checkpoints from the main active learning run into `Model/`.
   - Ensure the models are named STRICTLY in the format `<arch>_<strategy>_<variant>_model.pt`
   - E.g., `efficientnet_b4_entropy_dual_metric_model.pt`

   > [!WARNING]  
   > **Naming Convention & Missing Models**  
   > The evaluation script parses the filenames to group models into pairs (Baseline vs Dual-Metric) for the final comparison charts.  
   > - If a file does not follow the exact naming convention, the script will print a warning and **skip it entirely**.  
   > - If you provide an incomplete set of models (e.g., fewer than 24, or missing the baseline counterpart to a dual-metric model), the script will still evaluate what is there. However, it requires complete pairs (both `uncertainty_only` and `dual_metric` for a given architecture/strategy) to generate the side-by-side comparison plots. Unpaired models will be excluded from the final comparison charts.

## Running the Evaluation

Once the files are in place, run the evaluation script:

```bash
python run_ood_evaluation.py
```

## Outputs

The script dynamically builds out the following folder structure to store evaluation results:

1. **`results/`**: 
   - Stores the raw output for *every* model evaluated. 
   - Includes individual predictions, confusion matrices, and metrics stored in JSON format.
   - **Note on Naming**: If a model is incorrectly named (e.g., `myModel.pt`), its results will *always* still be successfully evaluated and deposited here.

2. **`Compared_Results/`**: 
   - Stores side-by-side performance comparison charts, generated by pairing a Dual-Metric model against its Baseline counterpart (e.g. `resnet50_entropy_dual_metric` vs `resnet50_entropy_uncertainty_only`).
   - **Note on Naming**: Incorrectly named models (like `myModel.pt`) or unpaired models are explicitly excluded from this folder, as the script cannot determine their pair.

3. **`All_Compared_Results/`**: 
   - Stores the master summary tables (`.csv` and LaTeX) and grand aggregate charts comparing all models simultaneously.
   - **Note on Naming**: Incorrectly named models will appear in these master charts as an "unknown" pair.
